## 무게감 조절 손잡이

색 개수(진중할수록 ↓) · 파스텔 유무 · 다크 페이지 비율 · 카피 어미(존댓말 완결문 ↔ 구어) ·
라운드 반경(진중할수록 작게) · 장식 밀도.

- **정보 밀도도 톤이다 (2026-07-13 확정)**: 제안서·보고서는 y0.12~0.86까지 더 빽빽하게
  (심사자가 밀도에서 성의를 읽음), 필수 구조물(예산표·책임 분계·일정표·목표 근거·출처) 포함.
  같은 골격(가로 3카드) 반복 금지 — 페이지마다 표/타임테이블/2단/도식으로 구성을 바꾼다.
  얕은 랜딩페이지 카피가 아니라 근거 있는 실무 문장으로.
- 애매하면 **보수적(진중한) 쪽이 기본값** — 캐주얼은 근거가 있을 때만.
- 판단 결과는 작업 시작 보고에 한 줄로 명시
  ("공공 제안서로 판단, gyoan 정적 구성으로 갑니다").

# 3. 테마 탐색 순서

1. `projects/<slug>/themes/<name>.json` — 프로젝트 전용
2. `pptm/design/themes/<name>.json` — 공용
3. `pptm/design/gyoan.py`의 `THEMES` — 내장

layout_spec의 `"theme": "<name>"`이 자동 탐색. **빠진 키는 gyoan에서 상속**(부분 정의 OK).
일회성은 layout_spec에 `"theme_tokens": {...}` 인라인.

# 4. 새 테마 만들기

## 절차
1. `docs/design-refs-getdesign.md`(서구 브랜드 문법) 또는 `docs/design-refs-kmong.md` §1
   (한국 실무시장 문법)에서 어울리는 문법을 고른다. 없으면 `docs/designmd_raw/<brand>.md`
   원문(22종)을 읽고, 그것도 없으면 `npx getdesign@latest add <brand>`로 새로 받는다.
2. 팔레트·타이포 규칙을 테마 토큰으로 번안 — 한글 폰트는
   `docs/design-refs-getdesign.md`의 "한글 폰트 → 용도 매핑" 표에서 성격이 맞는 것을 고른다.
3. `pptm/design/themes/<name>.json` 작성 (**코드 수정 불필요**) → layout_spec에 `"theme"` 지정
   → `pptm rendernative <slug>` → 썸네일 육안 검수.

## 번안 원칙 (실패에서 배운 것)
- **제목·소제목(display_b)은 반드시 Bold~ExtraBold** (2026-07-13 사용자 확정):
  원전이 weight 300/330/400 씬 디스플레이여도 한글 헤드라인은 굵게 번안한다 —
  한글은 획이 복잡해 얇으면 빈약해 보인다. "가벼움" 정체성은 색·여백으로 표현.
  얇은 웨이트는 보조 텍스트·라벨·serif 슬롯에만.
- **색만 바꾼 테마는 반려된다** — 서피스 문법과 시그니처 무브까지 가져올 것
  (예: 서피스 교대, 피처드 플립, 컬러블록 1개 규칙, 폴라리티 밴드).
- 원전의 "Avoid" 목록은 그대로 지킨다 (예: Apple에 두 번째 악센트 금지).
- ALL-CAPS 의존 시스템(Discord류)은 한글 번안 불가 — 모노 라벨로 우회하거나 포기.
- 다크 커버 블룸은 intensity 0.6 안팎이 안전 — 1.0이면 하단 텍스트가 묻힌다.
