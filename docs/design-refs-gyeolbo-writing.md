# 결과보고서(결보) 작성 규칙 — MIT GSW 결보 실물 학습 (2026-07-14)

원전: 사용자가 실제 완성·납품한 `결과보고서_MIT.pptx`(39장, Moduus Studio). 블랙 템플릿을
기계적으로 채우는 것과 완전히 다르다 — **결보는 관공서 개조식 문서**다. 아래 규칙을 반드시 지킨다.

## §0. 결보 절대 체크리스트 — 시민교육 결보 6차 반려로 확정 (2026-07-17)

다음 결보를 만들 땐 **시작 전에 이 목록부터 세팅**한다. 전부 사용자가 반려·지시로 확정한 것.
구현 전량은 `projects/gyeolbo-civic/build/build_final.py`(참조 구현) + `validate.py`(검수기).

**제작 방식**
1. MIT pptx = 규칙서. **통째 복사 → 문단 단위 인플레이스 교체(rPr 불변) → 사진 교체 → 재배열**.
   완성본을 다시 열어 재저장 금지(zip 파트 중복 손상) — 항상 빌드 스크립트를 고쳐 재빌드.
2. MIT에 맞는 셀이 없으면 규격을 직접 만든다(§13, make_photo_page) — "MIT에 없으면 못 해?" 금지.
3. **모르거나 애매하면 반드시 사용자에게 물어본다** (항구 지시). 임의 각색 = 반려.

**사실 원칙 (§15·§18·§23)**
4. 수치·운영 방식·홍보 채널 전부 **증빙 있는 것만**. 기획 대화(facts.md)는 사실이 아니다.
   미집계는 "최종 집계 후 확정" 각주. 안 한 일(지자체 게시, 동선 안내)은 골격이 요구해도 쓰지 않는다.
5. 수량·쪽번호는 전부 **실측·자동 계산** (파일 세기, PAGE_ORDER.index) — 하드코딩은 즉시 거짓이 된다.

**내용 구조**
6. 개요 첫 장 '핵심 결과 요약' = **사람 수와 결과** (구분|결과|산출 기준 3열: 참석·일자별 출석·
   연인원·수료·수료율·달성률) — 결보에서 제일 먼저 보는 자리 (§12.1).
7. 교육'행사' — 골격 명칭은 '행사 개요·행사 내용' (§12.2). 문체는 개조식 명사종결 (§1).
8. **강사 이력 페이지 필수** (§19.4·§21.3): 프로필 표 = [헤더 3열 병합 + 사진 열 세로 병합·원형
   헤드샷 오버레이 + 틴트 구분 열] + 경력 표('-' 채움 금지). 내용은 강의자료 SPEAKER에서.
9. 산출물 내역·제출 자료 표(발주처 정산 대조용), 참석 서명부(인명부) 페이지 포함 (§17).

**자산 배치**
10. 제공 폴더는 `find` 전체를 truncate 없이 훑고 **거의 다 쓴다** (영상 제외, `X (1).jpg` 사본은
    원본 있을 때만 제외). 같은 자산을 두 페이지에 반복 금지, 이미 보여준 자산의 재탕 페이지 금지 (§23.3).
11. 홍보 캡처 = **MIT S21 규격 그대로** (2.51×4.38, 2열×2행, 셀마다 캡션) + **채널별 분리**
    (오픈채팅/인스타·스레드/에타, 카드뉴스 vs 포스터 구분) + 크롬 크롭(상단 잉크 감지, 하단 비율 역산) (§16).
12. 문서형 캡처는 내용이 다 보여야 한다: 넓은 시트는 목표 셀 높이에서 **스트립 폭 역산** 후 2열 (§21.1),
    스크린샷은 흰 패딩(_pad_ratio). 예외: S7 구글폼은 포스터와 동일 셀로 force_crop (§20.1).
13. 세로 배너(1:3)는 단독 페이지 (§20.4). 성격 다른 자산을 쌓으면 블록마다 캡션, 캡션 ≤12유닛 assert (§19.1).
14. 사용자 제공 이미지는 받는 즉시 `conv/src_*.jpg` 영구 보관 — image-cache는 증발한다 (§22.2).

**레이아웃**
15. **모든 페이지 마지막 개체 하단 = 안내선(10.05), 캡션은 10.16** — 솔버로 기계 보증 (§22).
    확대 크롭 전면 금지(디자인물 글자 잘림), 부족분은 간격 이분 탐색.
16. 하단 여백 금지·같은 골격 반복 금지·불릿 슬롯 줄수 준수 (§10). 표 행 추가는 addnext (§11·§19.3).

**검수**
17. `validate.py` 0건(의도된 크롭 제외) + 썸네일 Read로 전 페이지 눈 검수 + 잔재 스캐너(BAD)에
    반려 문구 등록. PER 키 삽입 후 grep으로 목적 dict 확인 (§23.4).

⚠ **시민교육 결보 최종본(바탕화면)은 2026-07-17 사용자가 직접 최종 수정함 — 재빌드로 덮어쓰지 말 것.**
재빌드가 필요하면 다른 파일명으로 출력해 대조부터.

## 1. 문체 (제1 규칙 — 어기면 반려)
- **전 문장 개조식 명사종결**: `~함 / ~하였음 / ~정리함 / ~기여함 / ~판단됨 / ~필요 있음`.
  "~했다/~하였다/~된다" (다체) 금지. 예:
  - "학생 서포터즈를 홍보팀과 운영팀으로 구분하여 운영함."
  - "목표 대비 초과 달성한 결과로 판단됨."
- 리드 문장 정형: "「○○」은 ~를 위해 추진됨. 본 장에서는 ~를 중심으로 정리함."

## 2. 페이지 밀도 구조 (제2 규칙)
콘텐츠 페이지 1장 = **[절 제목(레드 필)] + [수행내용 불릿 5~6줄] + [3열 표] (+증빙 사진)**.
여백 성기게 두지 말 것. MIT는 거의 모든 내용 페이지가 이 3단 구성이다.
- **수행내용 불릿**: 활동을 구체적으로. "온라인 지원서를 통한 지원자 접수 및 기본 인적사항,
  소속, 연락처, 활동 가능 일정, 희망 역할, 관련 경험 수집" 수준의 디테일. 4~6개.
- **3열 표 정형**: `구분 | 수집항목/주요내용/관리항목/취합항목 | 활용목적` 이 패턴이 반복.
  헤더는 레드 필+백색 볼드, 본문 행은 흰 셀+하단 하어라인.

## 3. 성과 정리 (제3 규칙)
- **목표 대비 실적 표**: `성과항목 | 목표 | 실적 | 초과분 | 성과해석`. 달성률 %까지.
- **빅넘버 카드** + **전환 퍼널**(게시 → 클릭 → 신청완료, 각 단계 수치).
- **운영결과 요약표**(2열: 구분 | 운영결과).
- 실집계 전 수치는 지어내지 말고 "최종 집계 후 확정 기재" 각주.

## 4. 증빙자료 (제4 규칙)
- "이미지 및 증빙자료" 섹션 + `▲ 캡션` 다수. 모집공고·구글폼·응답시트·합격문자·오픈채팅방·
  OT자료·홍보게시물(인스타/에타/링크드인/스레드)·현장사진·발표자료·시상사진 등.
- A4 통짜 증빙 이미지 페이지, 2~8분할 그리드 페이지 적극 활용. 사진은 **장면마다 다른 컷**을
  골라 캡션을 각기 붙임(같은 컷 반복 금지).

## 5. 표준 목차·장 구성
- **01 과업추진 개요**: 추진 배경 및 목적 / 행사 세부 일정 / 인력 구성 및 역할 / 운영 로드맵
- **02 과업 수행 내역**: 모집·선발 관리 / 홍보 활동·참여자 모집 / 본 행사 운영 지원 /
  (성과보고회 준비) — 각 절 [수행내용 불릿 + 3열 표 + 증빙]
- **03 과업 수행 결과**: 전체 운영 결과(요약표+빅넘버) / 부문별 성과 / **종합 성과 및 개선사항**
- **04 산출 내역**: 소요예산 표(항목|세목|산출내역|금액)

## 6. 마무리 = 종합 성과 및 개선사항

실측한 결과. **제작법은 MIT 파일을 통째 복사→도형 텍스트/표셀만 인플레이스 교체(rPr 불변)→

### 8.3 표 스타일
- 헤더행 = 레드(#D80C18) 채움 + 흰색 볼드(일부 좌→우 오렌지 그라데). 본문행 = 흰 셀,
  첫 열만 연레드 틴트(#FDF0F0). 셀 하단 얇은 헤어라인, 세로선 없음(개방형).
- `a:tableStyleId` 제거 → 파워포인트 기본 파란 밴딩 방지.
- **표 셀은 내용이 길면 자동 줄바꿈+행높이 증가 → 오버플로 안전** (아래 8.6).

### 8.4 인포그래픽 도식 (템플릿 내장 요소를 그대로 재사용)
- **스텝 체인**: [라벨필 페이퍼로지7B] + [부제 Pretendard8] 카드 N개를 » 로 연결. 라벨 4~10자.
- **빅넘버 3연**: 상단 레드필 라벨 + 일러스트 + 대형 숫자(D80C18, ≤8자) + 하단 부제 1행.
- **전환 퍼널**: 5단 화살표(게시→접속→신청→확정) + 각 단 [지표명]+수치.
- **조직도**: 3열 박스(제목필 + 헤더바 + 불릿4), » 연결.
- **좌측 레일 라벨**: 좌여백에 레드 언더바+화살표+장/절 라벨.
- 규칙: 도식 안 글자는 **칸 폭에 맞춘 짧은 구절**(라벨 4~10자, 부제 1행). 길면 즉시 넘친다.

### 8.5 사진 규칙
- 그리드 = 2열×N행 동일 크기 칸(예 2.51×1.41in 가로), 12칸/페이지. 증빙 세로물(포스터·배너)은
  세로 슬롯(예 2.51×3.54in). **사진은 박스에 센터크롭으로 꽉 채움**(crop_l/r 또는 t/b 대칭, 레터박스 금지).
- 각 사진 아래 `▲ 캡션`(Pretendard 10). 장면마다 다른 컷, 같은 컷 반복 금지.

### 8.5b 사진/이미지 셀 크기 2종 (2026-07-15, 사용자 지정)
- **강의자료(PPT→PNG, 16:9 슬라이드)**: MIT **S13·S29·S15식 16:9 셀(2.51×1.41)**에 배치 → 슬라이드가
  잘림 없이 딱 맞음. 일차별 12장(2×6 그리드). 강의 PDF→PNG는 사용자 제공 폴더(강의자료/N일차.png/).
- **현장 사진(폰 촬영 4:3)**: MIT **S17·S26식 세로 셀(2.51×1.75)**에 배치 → 4:3 사진이 덜 잘림.
- 두 크기를 섞지 말 것(슬라이드를 세로셀에 넣으면 여백, 폰 사진을 16:9셀에 넣으면 과잉 크롭).
- 셀보다 큰 이미지는 center_crop으로 채움. 캡션은 필 폭에 맞춰 짧게(≤15유닛).

### 8.6 오버플로 예산 (네모칸 벗어남 방지 — 실측·필수)
- 유닛길이 = Σ(한글 1.0, 영문·숫자·기호 0.55). **인플레이스 교체문을 원문 유닛길이 이하로 유지하면
  100% 안전.** 초과 시 아래 유형별 처리:
  - **단일라인 불릿**(수행내용·활동 리스트, 촘촘히 쌓임): 1줄 = 한글 **~44자(유닛) 상한**.
    넘으면 2줄로 감겨 **아래 불릿과 겹침** → 반드시 상한 이내. 나열은 쉼표 대신 중점(·)으로 폭 절약.
  - **문단 블록**(챕터 리드·배경·목적): 다중행 박스라 여유 큼(원문 +20유닛까지 안전).
  - **표 셀·빅넘버**: 표는 자동 줄바꿈 안전, 빅넘버는 ≤8자.
- 절차: 빌드 후 교체문 유닛길이를 원문과 비교해 초과분 리포트 → **단일라인 불릿 초과분만 실측 렌더로
  겹침 확인 후 트림.** (build 스크립트에 OVERFLOW AUDIT 내장.)

### 8.7 검증 절차
1. `pdftotext` 전문에서 원전 잔재(서포터즈·해커톤·수치·MIT 등) 0건 확인 (이미지 Read는 경로 캐시 주의).
2. LibreOffice 렌더는 **잔존 soffice 인스턴스가 옛 결과를 캐시**하므로 `pkill -9 soffice` 후
   `-env:UserInstallation`으로 새 프로필 변환. python-pptx의 **표 좌표는 실제 렌더 위치와 다를 수 있어**
   온캔버스 필터 대신 전 도형에 교체 적용.

## 9. 레이아웃·여백 그리드 (자율 배치용 — 실측, 2026-07-15)

MIT 내지 세로 리듬을 절대좌표로 실측. **이 그리드를 알면 MIT 슬롯에 갇히지 않고 요소를 직접
원하는 y에 배치해 조립 가능**(요소는 프리미티브 재현이 아니라 MIT 디자인 컴포넌트를 복제해 사용).

### 9.1 페이지 그리드 (7.5 × 10.833 in)
- **콘텐츠 컬럼: x 1.90 ~ 6.98 (폭 5.08)**. 좌측 레일 존: x 0 ~ 1.90(라벨·아이콘). 우측 여백 0.52.
- 내지 콘텐츠 시작 y ≈ **0.80**, 하단 한계 y ≈ **10.2**. 푸터 y 10.42.
- 헤더: 문서명(x0.55 sz8) 좌 · 스튜디오(x5.81 sz10) 우. 푸터: 페이지번호(x0.52)+장라벨(x0.77 sz8) 좌.

### 9.2 세로 리듬 (내지 — 실측 간격, inch)
- 소제목 **PILL**(페이퍼로지 8EB sz10, 🔴아이콘 풀바) 상단 y≈0.80, x2.21
- **PILL → SUB** 간격 **0.33**
- **SUB**(▷ 페이퍼로지 6SemiBold sz10, x2.09) **→ 첫 불릿** 간격 **0.25**
- 불릿(Pretendard ~10.5, ◆ x2.10) **stride 0.27** (1줄 기준). 줄바꿈 1줄당 +≈0.20
- **불릿블록 → 다음 SUB** 간격 **0.47 ~ 0.57**
- 표: 직전 블록 끝 + ≈0.5, x1.90 폭5.08. 사진 그리드: 2열(x1.90 / 4.47), 칸 폭 2.51.
- 사진 **캡션 ▲**(Pretendard10): 사진 하단 바로 아래.
- **좌측 레일 라벨**(페이퍼로지 8EB sz12, red, x0.52): 담당 섹션 상단 y에 정렬.

### 9.3 챕터 디바이더
- 장번호(나눔스퀘어라운드 60, x0.52 y0.67) · CHAPTER(x0.52 y1.54 sz10 red) · 장제목(페이퍼로지 40,
  x1.90 y0.82) · 리드문(Pretendard 10, x1.90 y1.81, 폭5.08, 3~4줄 개조식).

### 9.4 배치 규칙 (조립 시)
- 한 내지 = [소제목 PILL] + (SUB + 불릿 4~6줄)×N + [표/인포그래픽] + [증빙 사진+캡션]. y0.8~10.2 채움.
- 새 SUB 블록은 직전 블록 끝 + 0.5. 불릿은 stride 0.27 등간격, 2줄 불릿 뒤엔 +0.2 보정.
- 모든 콘텐츠 x1.90 정렬(소제목 아이콘 x1.9 시작, 불릿 텍스트 x2.10 들여쓰기).
- 좌측 레일 라벨은 섹션 상단 y에 맞춰 x0.52에 배치(섹션당 1개, 진한 레드).
- **조립 = MIT 디자인 컴포넌트(pill/SUB/bullet/table/스텝칩/조직도/빅넘버)를 deepcopy 복제 → 그리드 y에
  위치·텍스트만 세팅.** 새 도형을 프리미티브로 그리지 말 것(반려 이력). 오버플로는 §8.6 예산 준수.

## 10. 정밀 배치 규칙 (사용자 추가지침 2차, 2026-07-15)

인플레이스/조립 후 반드시 적용하는 미세 조정. build_final.py의 `normalize_table`·`even_bullets`로 구현.

### 10.1 하단 여백 금지 (⚠️ 사용자 "진짜 중요" 재강조, 2026-07-19)
- 내지 콘텐츠는 **하단 안내선(y≈10.2)까지 채운다**. 콘텐츠가 상단에서 끝나 하단이 비면 안 됨.
- **왜**: 하단 여백은 독자에게 "**이 장이 끝났다**"는 신호로 읽힌다. 그래서 **다음 장으로
  넘어갈 때가 아니면 여백을 만들면 안 되고, 내용을 하단까지 쭉 이어붙여야** 한다. 한 페이지에서
  내용이 상단 60%만 채우고 끝나면 그 페이지가 절(장)의 마지막처럼 보여 흐름이 끊긴다.
- **여기서 '장' = 목차의 4개 대제목**(01 과업추진 개요 / 02 과업 수행 내역 / 03 과업 수행 결과 /
  04 교육 만족도 조사 결과). 이 대제목이 바뀌는 경계 = 챕터 디바이더 직전 페이지·디바이더
  페이지에서만 하단 여백이 정당하다. **같은 장 안의 내지끼리는 여백 없이 연속**이어야 한다.
- 채우는 법: 증빙 사진+캡션·표 행 추가(§19.3)·불릿 슬롯 확장·2열 배치로 하단까지. MIT 슬롯
  재사용 시 대개 자동 충족되지만, 복제·삭제로 성긴 페이지는 반드시 아래를 끌어와 채운다.

### 10.2 불릿 줄 간격 균등 (⚠️ 함정 주의 — 실전 검증)
- **top-level 불릿 런만** justify(첫·끝 y 고정, 등간격 stride)로 균등화. **적용 조건: 추정 stride
  0.24~0.55(=1줄 불릿)일 때만.** 2줄 불릿을 justify하면 stride가 줄 높이보다 작아져 **겹친다** —
  반드시 배제. (gap모델로 줄높이 반영하려다 되레 S11 운영체계 불릿을 깨뜨림 → 단순 justify가 안전.)
- **그룹 안에 중첩된 불릿**(예 S39 종합성과/개선사항 = 그룹 [34]/[35] 자식)은 even_bullets가
  **못 건드림**. 여기에 2줄 텍스트가 들어가면 MIT의 1줄 슬롯과 겹친다 → **텍스트를 1줄(≤40유닛)로
  줄여** 해결(§8.6 오버플로 예산). 위치 이동 아님.

### 10.3 표 본문 행 높이 균등 (⚠️ 행높이 명시설정 금지)
- **행 높이를 코드로 명시 설정하지 말 것.** LibreOffice엔 맞아 보여도 **파워포인트에선 설정값이
  콘텐츠보다 크면 셀 하단에 여백**이 생긴다(사용자 지적).
- 대신 **10.4의 1열 한 줄화로 콘텐츠를 균일**하게 만들면 파워포인트가 행 높이를 콘텐츠에 맞춰
  **자동 균등**해준다(성과지표 표: col0 2줄→1줄 되면 모든 행 1줄로 균등). 이게 정답.
- 진짜 콘텐츠가 다른 표(커리큘럼 등)는 원래 행 높이가 달라야 정상 — 건드리지 않는다.

### 10.4 표 1열(제목열) 한 줄 맞춤
- 1열이 살짝만 넓히면 한 줄로 되는 경우(예 '참여자 모집'→2줄) **열 폭을 미세하게 넓혀 한 줄화**
  (가장 넓은 다른 열에서 차감). **짧은 제목열만**(≤7유닛). '1일차 09:00~09:30'처럼 **긴 열은
  건드리지 말고 2줄 유지**(넓히면 내용열이 좁아져 되레 줄 늘어남).

### 10.5 사진·캡션 매칭
- 사진 아래 `▲ 캡션`은 **그 사진이 실제로 보여주는 장면**과 맞게. (등록배너 사진 → '▲ 교육 안내
  배너', 실습 장면 → '▲ 교육생 실습 현장'.) 이미 대체로 맞으면 소폭 다듬기.

## 11. 인플레이스 리스킨 함정 5종 (실전 사고 기록, 2026-07-15)

MIT 결보를 통째 복사해 텍스트·사진만 갈아끼울 때 **실제로 터진** 것들. 전부 렌더 검수로만
잡힌다 — PPTX만 보면 정상으로 보이는 게 함정이다.

### 11.1 ⚠️ 화면의 표가 '표'가 아니라 '그림'일 수 있다 (제일 위험)
- **사고**: 개요 첫 장(S3) '핵심 결과 요약'을 3열로 고치고 수치를 다 넣었는데 **렌더는 MIT
  원문(1,211명 이상…) 그대로**. 원인: MIT가 표 **스크린샷을 그룹 안에 PICTURE로 박아** 놓고,
  편집용 진짜 표는 **캔버스 밖(x9.89)에 파킹**해 둠. 표를 고쳐도 화면은 그림이라 안 바뀐다.
- **진단법**: `pdftotext`에 표 글자가 **하나도 안 잡히면 그림**이다. (렌더 이미지만 보면
  '표를 못 고쳤나' 하고 엉뚱한 데를 판다.)
- **해결**: 그룹 안 PICTURE를 제거하고 **진짜 표를 그 자리 좌표로 이동**(`_unpin_table_image`).
  그룹 자식의 절대좌표는 `p:grpSpPr/a:xfrm`의 chOff/chExt로 스케일해야 한다
  (**grpSpPr는 `p:` 네임스페이스, 그 안의 xfrm은 `a:`** — 헷갈리면 NoneType 에러).
- **상시 감사**: 빌드 끝에 **캔버스 밖 표 스캔**을 돌린다. 파킹 표 = 그림으로 대체됐다는 신호.
  (단 '순서/주요 내용/운영 포인트' 7×3은 MIT가 여러 장에 남긴 미사용 복제본이라 무해.)

### 11.2 도형 순서 ≠ 화면 순서
- **사고**: 포스터/명찰이 서로 바뀌고(S7), 홍보 캡처 4장 캡션이 전부 어긋남(S21).
- **해결**: **캡션이 사진 내용을 지목하는 그리드**는 사진을 `(top, left)` 순으로 정렬해 채운다
  (`swap_pics(..., visual=True)`). 캡션 없는 일반 현장 그리드는 순서 무관.

### 11.3 불릿 균등화는 '같은 줄 수'끼리만 (10.2 보강)
- **사고**: S37 '등록·안내·동선' 3불릿이 겹침. MIT는 **1줄 불릿 Δ0.24 / 2줄 불릿 Δ0.44**로
  일부러 다르게 주는데, 균등화가 전부 Δ0.317로 맞춰 2줄 불릿이 아래를 덮었다.
- **해결**: `even_bullets`는 **박스 높이(h)가 같은 런**끼리만 묶는다(1줄 h≈0.29, 2줄 h≈0.49).
  소제목 라벨(h≈0.27)도 자연히 빠진다. MIT 리듬이 이미 정답이므로 **안 건드리는 게 이득**.

### 11.4 셀 끝 빈 문단이 그 행만 부풀린다 (10.3 보강)
- MIT 2문단 셀에서 둘째 문단을 `''`로 비우면 **빈 줄이 남아** 그 행만 높아진다.
- **해결**: 행 높이를 명시 설정하지 말고(파워포인트 하단 여백 유발) **셀 끝 빈 문단을 제거**
  (`strip_empty_tail_paras`). 내용이 균일해지면 행 높이는 자동으로 맞는다.

### 11.5 원문이 2줄인 자리는 2줄로 채워라
- 내 문장이 1줄로 짧아지면 그 자리에 **빈 줄이 남아 불릿 리듬이 깨진다**(S34). 위치를 옮기지
  말고 **문장을 원문 줄 수에 맞춰 쓴다**. 반대로 넘치면 1줄로 줄인다(§8.6).

### 11.6 캡션 필은 ~9유닛 (§8.6의 15유닛은 낙관치 — 실측 정정)
- `▲ 강의·실습 현장`(7.9유닛) OK / `▲ 강의·실습 현장 (1~2일차)`(13유닛)는 **필 밖으로 삐져나옴**.
- **회차·차수 같은 부가 정보는 캡션이 아니라 좌측 레일 라벨에** 넣는다(레일은 2줄까지 여유).
  예: 레일 `교육 현장 사진 ① (1~2일차)` + 캡션 `▲ 강의·실습 현장`.

## 12. 결보 내용 체크리스트 (자체 작성 결보 2건 역산, 2026-07-15)

### 12.1 개요 첫 장 = 사람 수와 결과 (가장 중요)
- 결보를 받아든 사람이 **제일 먼저 보는 건 몇 명 왔고 결과가 어땠나**다. 개요 첫 장의
  **'핵심 결과 요약' 표가 그걸 위해 존재**한다 — 개요를 반복하지 말 것(모집규모·교육주제 등 ✗).
- 표 디자인은 그대로 두고 **행·열만 목적에 맞게 재구성**: `구분 | 결과 | 산출 기준` 3열.
  행은 원본 개수를 유지(늘리면 아래 문단을 밀어 하단이 넘친다). 열 추가는
  `tblGrid/gridCol` + 각 `tr`의 마지막 `tc`를 deepcopy하면 채움·테두리·폰트가 그대로 승계된다.
- 담을 것: 모집 목표 / 총 참석 / 일자별 출석(연인원) / 수료 인원 / 수료율 / 목표 대비 달성률.
  각 행에 **산출 기준**을 병기(예 '수료 30명 / 참석 38명 (목표 70%)') — 심사자는 근거를 본다.

### 12.2 '교육 행사'다 — 행사 개요 / 행사 내용
- 이건 교육'행사'이므로 골격 명칭은 **행사 개요·행사 내용·행사 세부 일정**(MIT 원문 유지).
  '교육 개요'로 바꾸지 말 것. 내용물(커리큘럼·교육 운영 성과 등)에는 '교육'을 쓴다.

### 12.3 인원 지표의 표준 산식
- **총 참석**(1회 이상 참석) / **연인원**(일자별 합) / **회차 평균**(연인원÷회차) /
  **수료**(이수 기준 충족) / **수료율**(수료÷총 참석) / **목표 대비 달성률**(총 참석÷모집 목표).
- 실측 예: 26·32·27명 → 연인원 85, 평균 28.3 / 참석 38 / 수료 30 → 수료율 78.9%, 달성률 152.0%.
- **미집계 항목은 지어내지 말고** '조사 집계 후 확정' 각주로 남긴다(만족도·재수강 의향·예산).

### 12.4 결보에 있어야 할 것 (아이디어브릿지 결보 목차 역산)

## 14. 검수는 눈이 아니라 기계로 (validate.py)

LibreOffice 렌더는 파워포인트와 다르다 → **눈 검수는 사용자 화면을 대변하지 못한다**.
`projects/gyeolbo-civic/build/validate.py` 는 실제 폰트 파일(Paperlogy/Pretendard)로 글자 폭을
재서 렌더 없이 검사한다. 빌드 후 **반드시 0건**을 확인할 것.

| 검사 | 잡는 사고 |
|---|---|
| XML 스키마 | `a:tr`=(tc*, extLst?) 위반 → 파워포인트가 셀을 버리고 파란 기본 셀 생성 |
| 표가 아래 요소 침범 | 표 실측 높이 = Σ줄수×0.202 + 행수×0.081. 선언 높이를 넘어 자란다 |
| 표 셀 과다 줄바꿈 | 3줄 이상 감김 |
| 불릿 겹침·빈틈 | 실측 줄 수로 텍스트 높이 산출 → 다음 불릿 y 침범 / 원문 2줄 자리에 1줄 |
| 사진 잘림 | 셀 비율 vs 이미지 비율 → center_crop 손실률 25% 초과 |
| MIT 잔재 | MIT·서포터즈·해커톤·1,211·Lovable·09:00~12:00 등 |

### 14.1 이번에 이 검수기가 잡은 실제 사고
- **표 셀 추가는 `append` 금지, `last_tc.addnext()`** — extLst 뒤에 붙으면 파워포인트만 깨진다.
- **셀 여백**: MIT는 날짜/시간 셀에 `marL=marR=0`을 준다. 원문이 짧았던 행은 기본 여백이라
  긴 날짜를 넣으면 그 행만 줄바꿈이 깨진다 → `_zero_cell_margins()`.
- **1열 폭**: '00:00~00:05'(0.74in)와 '1일차 13:00~13:10'(1.03in)은 다르다. 가용 0.76in을 넘으면
  8행 전부 2줄 → 표가 0.6in 자라 아래 필을 덮는다. **폭을 넓혀 1줄로**(1.25in).
- **이미지 캐시 키는 반드시 원본 파일명 기준**. 인덱스로 키를 만들면 필터를 바꿨을 때 같은
  tag+번호에 다른 원본이 매핑돼 **옛 이미지가 조용히 재사용**된다.
- **전각 숫자**: MIT 챕터 번호가 `'0２'`(반각0+전각２)라 두 글자가 다른 폰트로 잡혀 줄이 넘어간다
  → 전각 숫자 일괄 반각 정규화.
- **dict 키 충돌**: 로드맵 표의 'MIT GSW 2026'이 1·2일차 두 행에 있어 두 행이 같은 값으로 덮였다
  → 표는 **위치 기반 post_*()로 통째 세팅**.

## 16. 홍보 캡처 배치 — MIT 규격을 그대로 쓴다 (2026-07-16 반려로 확정)

> "홍보한거 단톡방 사진도 크기 잘 맞춰서 2열이나 3열로 만들고 / MIT 결보에 홍보 단톡방 규격
> 적절하게 나와있잖아 이 한장 총 칸에 맞게 이쁘게 잘 하면 되는걸 / 카드뉴스로 홍보한거랑 그냥
> 일반 포스터로 홍보한거 그리고 인스타그램·에브리타임·단톡방·스레드 이런것도 잘 구분해서 올려야지"

**임의로 열 수를 늘려 축소하지 말 것.** 3열 0.53으로 우겨넣었다가 "너무 작아 안 보인다"로 반려됨.

### 16.1 MIT 실측 규격 (그대로 복제해 쓴다)
| 슬라이드 | 셀 | 비율 | 배치 | 캡션 |
|---|---|---|---|---|
| **S21** | 2.51×4.38 | 0.573 | **2열×2행 = 4장/쪽** | 셀마다 1개 (y5.31 / y10.16) |
| **S10** | 2.51×3.86 / 2.51×4.74 | 0.65 / 0.53 | 2열×2행, 위아래 블록 규격 다름 | 셀마다 1개 |
| **S22** | 2.51×1.52 | 1.645 | 2열×5행 = 10장/쪽 | 블록마다 |
- 셀 x = **1.90 / 4.47**, 캡션 x = **2.26 / 4.83**(셀 하단 +0.36), 상단 y=0.82 / 하단 블록 y=5.67.
- **폰 세로 캡처(0.46)는 S21 규격(0.573)** — 위아래를 조금 잘라 채운다. 가로 캡처는 S22 규격.

### 16.2 채널별로 나눠라 (섞지 말 것)
캡션은 **채널명**으로: 카카오톡 오픈채팅방 / 인스타그램 / 에브리타임 / 스레드 / 온라인 게시판.
MIT도 '▲ 에브리타임 홍보물 게시' '▲ 인스타그램 카드뉴스 게시' '▲ 스레드 온라인 홍보 게시'처럼
**채널 + 홍보물 종류**로 구분한다. **카드뉴스로 홍보한 것과 포스터로 홍보한 것도 구분**할 것.

### 16.3 폰 크롬 제거 — 상단은 감지, 하단은 목표 비율에서 역산 (2026-07-16 구현·검증)
`top=0.052 / bot=0.075` 같은 고정값은 기기·앱마다 달라 **네비바(|||  ○  <)·상태바(SKT 3:30·배터리)가
남는다**(반려). 그렇다고 상·하단을 둘 다 감지하려 들면 안 된다 — **하단은 앱마다 형태가 달라
(카톡 입력창 / 안드 네비바 / 인스타 탭바) 감지가 불안정**하다. 실제로 통한 방법:

1. **상단 = 잉크 블록 감지**. 최상단 3행의 중앙값을 배경색으로 잡고, 그와 40 이상 다른 픽셀이
   0.4% 넘는 행을 "잉크"로 표시. **첫 잉크 블록(=시계·배터리)이 끝나는 y**가 상태바 경계다.
   블록 종료 판정은 `공백 > h*0.006`. 여유 `+h*0.010`을 더하고 **상한 `h*0.056`으로 클램프** —
   인스타 피드처럼 배경이 어두우면 스토리 트레이까지 잉크로 잡혀 356px까지 튄다.
2. **하단 = 역산**. `bot = h - top - (w / 0.573)`. 남길 세로를 셀 비율에서 거꾸로 구하면
   하단 UI가 정확히 잘려나가고 **결과 비율이 정확히 0.573** → center_crop 손실 0.
3. **상단을 보존하는 게 핵심**. 채널명(방 이름·계정명)이 헤더에 있다. center_crop에 맡기면
   중앙 기준으로 위아래를 깎아 **헤더가 잘린다**. 위는 감지로 최소만, 아래로 비율을 맞춘다.

실측 결과 15장 전부 0.573 정합 (iOS 1179×2556 → top 132 / bot 367, 안드 1080×2340 → 90 / 366).

### 16.4 캡션은 12.0유닛이 한계 (실측)
캡션 필 내부 폭 1.71in. `units()` 기준 **12.0을 넘으면 두 줄로 감긴다** —
'▲ 대구경북 대외활동 499명'(12.4)이 감겨 나왔다. MIT 원문('▲ 홍보 A팀 인스타그램 계정' 13.2)이
들어간다고 믿으면 안 된다. **빌드에서 assert로 막을 것**. 방 이름이 길면 축약하고 인원은 남긴다
(도달 규모가 홍보 성과다): `▲ 대외활동방 499명`.

### 16.5 페이지를 늘렸으면 목차 쪽번호는 자동 계산
홍보를 2쪽→4쪽으로 늘리자 03장 시작이 24→26쪽으로 밀렸다. `post_toc(slide, '24')` 같은
**하드코딩은 즉시 거짓말이 된다** → `PAGE_ORDER.index(33) + 1`로 계산하고, 호출은 **재배열 이후**에.
같은 이유로 산출물 내역의 수량도 전부 실제 파일을 센 값이어야 한다 (§15).

## 19. 블록별 캡션 · 강사 이력 · 여백 (2026-07-16 2차 반려 반영)

### 19.1 성격이 다른 자산을 한 장에 쌓으면 캡션도 블록마다
'▲ 홍보물·제작물' 하나로 명찰+카드뉴스+배너+현수막을 묶으면 무엇을 가리키는지 알 수 없다.
`make_photo_page(blocks=[(imgs, cols, ratio, '▲ 캡션'), ...])` — 4번째 요소를 주면 그 블록 아래에
캡션 필을 복제해 붙인다. 산출물+후기, 문자+대기화면+만족도화면도 마찬가지.
**캡션은 여기서도 12.0유닛 한계**(§16.4) — assert로 막는다. 실제로 '▲ 명찰 디자인 (강사·STAFF)'
(13.2) · '▲ 강의자료 관리 (구글 드라이브)'(15.2) · '▲ 참여자 후기 (교육 종료 후 수집)'(16.1)이
전부 걸렸다. 괄호 안 부연은 대개 빼도 된다.

### 19.2 하단 여백을 간격으로 채울 때 — 나누는 수는 '행수 − 1'
전폭(1열) 자산은 셀을 더 못 키우니(maxk=1.0) 간격으로 채울 수밖에 없다. 이때
`vgap = gap + (남는 세로) / nrows` 로 하면 **마지막 블록 뒤 몫이 허공에 배정돼 1in 넘게 빈다**.
간격이 실제로 들어가는 지점은 `nrows - 1`개다. 상한은 0.85(0.55면 여전히 빈다).

### 19.3 표에 행을 더해 하단을 채울 때
S11(운영 추진 체계)은 표가 3행이라 하단 0.86in이 비었다 → **확정 사실인 발주처 협조 행을 추가**해
채웠다(지어내서 채우지 말 것 §15). MIT 표는 행 수가 고정이므로 `add_table_row()`로 마지막 tr을
복제해 늘린다 — **`a:tbl` 자식 순서는 (tblPr?, tblGrid, tr*)이므로 append 말고 `addnext`**(§11).
반대로 **행을 늘리면 표가 커져 아래 요소를 침범한다** — 산출물 내역에 행을 더했다가 '제출 자료'
소제목과 겹쳐, 기존 행에 합쳤다(`명찰·교육장 안내 화면 | 명찰 2종 / 안내 6종`).

### 19.4 강사 정보는 결보 필수 — 참고 결보의 '초청 강사 이력' 구조
발주처가 강사 적정성을 확인하는 자리다. 참고 결보(2026 기술특허 특강)는
`강사명 / 근무처명 / 직위` 표 + `경력사항` 표로 쓴다. 우리는 S5(표 2개 페이지)를 복제해
[구분|강사 정보|비고] + [구분|주요 경력|성과|비고]로 구성. **내용은 강의자료의 SPEAKER 슬라이드
(1일차 04p)에서 그대로 옮긴다** — 강사 실적을 지어내면 안 된다(§15).
⚠ S5 설명문단 슬롯은 **y4.93=1줄(≤44유닛) / y5.24·5.95=2줄** — 3줄 쓰면 아래를 밀고 겹친다(§10.2).

## 20. 3차 반려 반영 (2026-07-16 밤) — 문서형 자산·강사 사진·비율

### 20.1 문서형 캡처는 fit_cell이 아니라 '목표 비율 크롭'
`GFORM`을 FIT_ASSETS로 두면 swap_pics가 셀을 이미지 비율(1.12)로 늘려 포스터 셀(0.709)과 크기가
달라진다(반려: "구글폼 좌우 잘라서 포스터랑 크기 똑같이"). → **S7은 `force_crop=True`로 center_crop**,
구글폼 좌우를 잘라 포스터와 동일 셀. 잘려 내용 일부가 사라져도 사용자가 그걸 원한 것(썸네일 증빙).
FIT_ASSETS는 이제 비우고, 문서형은 전부 make_photo_page 블록 ratio로 맞춘다.

### 20.2 같은 자산을 두 페이지에 반복 금지
구글폼(신청서)이 p08(모집)·p10(신청 접수)에 중복됐다(반려: "구글폼 2개 들어가있고").
→ 신청서는 모집 페이지에만, 신청 접수 페이지는 **응답 시트**만.

### 20.3 넓은 가로 자산(스프레드시트)은 좌/우 절반으로 쪼개 세로로 쌓는다
응답 시트(1.90, 가로로 넓음)를 전폭에 넣으면 세로 2.67in로 페이지가 빈다(반려: "좌우 딱 맞춰야지").
→ **좌 53% / 우 47%(6% 겹침)로 잘라 2개 블록으로 세로 스택.** 전폭(좌우 딱) 유지하면서
행이 2배로 커지고 페이지도 찬다. 캡션 "▲ 응답 시트 · 기본 정보 / · 응답 내용".

### 20.4 세로형 배너(1:3)는 단독 페이지 — 다른 자산과 섞지 말 것
X-배너를 명찰·카드뉴스·현수막과 한 장에 두면 세로가 넘쳐 **전체가 81%로 줌어들어 좌우 안내선이
안 맞는다**(반려). → 배너는 다음 장으로 분리. make_photo_page는 1열 세로 자산을 자동으로
가운데 정렬+세로 꽉 채움(좌우 여백은 배너 본래 비율이라 정상).

### 20.5 강사 사진은 표에 넣는다 (병합 셀 + 오버레이)
"표에 강사 사진 넣어서 자연스럽게"(반려: 강사 페이지가 최악). → 정보 표를 [사진 | 항목 | 내용]
3열로, **좌측 열을 세로 병합(cell.merge)하고 흰색 채운 뒤 원형 마스킹한 헤드샷을 오버레이**한다
(표 셀은 그림을 못 담으므로 add_picture로 위에 얹음). 헤드샷은 강의자료 SPEAKER 슬라이드에서
원형 크롭(PIL ellipse 알파 마스크). 값은 col2(2.45in)에서 1줄로 떨어지게 간결히.

### 20.6 안내 문자 2종 나란히 / 교육장 화면은 일자별 2열
사전 안내(SMS) + 당일 리마인드 문자를 2열로. 교육장 화면은 [대기 | 만족도]를 한 행으로 묶어
일자별 2열×3행(사용자 지시). 사용자가 채팅에 붙인 이미지는 `~/.claude/image-cache/<세션>/NN.png`.

## 21. 4차 반려 반영 (2026-07-16 밤) — 2열 배치·프로필 표 문법

### 21.1 넓은 시트 스트립은 '페이지가 정확히 차는 수'로 역산한다
좌/우 2분할 세로 스택(§20.3)도 반려됨("2열로 해줘"). 2열 배치에서 페이지를 채우려면
셀 높이 목표(ch = (avail − 캡션 0.34)/2행 − gap ≈ 4.36)에서 **스트립 비율을 역산**:
r = 2.505/4.36 = 0.574 → 스트립 폭 = r×(시트 h/w) ≈ 30.2%, 4개(이웃 7% 겹침) → 2열×2행.
좌우 딱 + 상하 꽉. 분할 수를 먼저 정하지 말고 **목표 셀 크기에서 거꾸로** 정할 것.

### 21.2 드라이브 캡처 2장 = 2열 한 행 + 아래를 콘텐츠로 채운다
가로형 캡처 2장을 1열 스택하면 반려("위에 두개는 2열로 하면 좋잖아"). 2열로 줄이면 생기는
하단 공백은 vgap이 아니라 **콘텐츠로** 채운다 — 일자별 [표지 | 개요 슬라이드] 2열×3행.
개요 슬라이드는 LEC 큐레이션(12장)에 안 들어간 index 3을 써서 강의자료 페이지와 중복 회피.

### 21.3 프로필 표 문법: 데이터를 row 0부터 쓰면 헤더가 데이터를 먹는다
MIT 표의 row 0 = 레드 헤더. 여기에 '강사명|백지헌'을 쓰면 이름이 헤더 자리에 박혀
"템플릿 분위기와 안 맞는" 표가 된다(반려). 정답 구조:
- row 0: **3열 가로 병합** `cell(0,0).merge(cell(0,2))` + '위촉 강사 프로필' (레드 필 유지)
- 사진 열: **row 1~N 세로 병합** + 흰 채움 + 원형 헤드샷 오버레이(셀은 그림을 못 담음)
- 구분 열: 템플릿 1열 틴트(#FDF0F0)를 데이터 행마다 수동 채움

## 22. 하단 안내선 정렬 엔진 (2026-07-16 확정 — 사용자 절대 지시)

> "무조건 엥간하면 내가 맞춰둔 아래 안내선에 개체 딱 맞게 세팅해. 다른 MIT 결보도 그렇게 했어."

**모든 그리드 페이지의 마지막 이미지 하단 = GY_MAX(10.05), 캡션은 그 아래 10.16 고정.**
간격을 눈대중으로 벌리는 방식은 어긋난다 — make_photo_page에 이분 탐색 솔버를 내장했다:

1. **셀 높이 배율 s 탐색, 상한 1.00 (확대 크롭 전면 금지)** — s>1로 채우면 center_crop이
   카드뉴스·표지·캡처의 가장자리 글자를 잘라먹는다("3일 동안"→"일 동안", 실제 반려).
   축소(s<1)만 경미하게 허용(초과 페이지, 예: 문자 캡처 1.6%).
2. **잔여분은 간격(vg) 이분 탐색** — s로 못 채우면 vg를 [gap, 1.20]에서 직접 푼다.
3. **마지막 캡션은 세로 예산에서 제외** — 포함하면 이미지가 0.4in 못 미친다. 극단 초과
   (배너 1:3)의 종횡 축소 배율도 `(total - 꼬리 gap - 마지막 CAP_H)` 기준으로.
4. **문서형 스크린샷은 흰 캔버스 패딩**(`_pad_ratio`) — 셀보다 세로가 짧은 캡처는 패딩을
   먼저 잘리게 해 내용 무손실.

결과: 그리드 8페이지 전부 `마지막 이미지 하단=10.05` 로그로 검증.

### 22.1 프로필 표: 병합 셀 필은 명시 지정
가로 병합(헤더)·세로 병합(사진 열) 후 **원본 셀별 필에 맡기면 병합 구간이 반쪽만 붉게
렌더된다**(반려). 병합 직후 origin 셀에 `fill.solid() + RGB(D80C18)`를 명시할 것.
경력 표에 '-' 채움 금지 — 성과·비고를 실제 내용으로 재배치.

### 22.2 사용자 제공 이미지는 받는 즉시 영구 보관
`~/.claude/image-cache/`는 세션 캐시라 **원본이 증발한다** (드라이브 캡처 2장 실제 소실 →
배포 pptx의 media에서 복구). 받은 즉시 `conv/src_*.jpg`로 저장하고 그걸 소스로 쓸 것.

## 23. 6차 반려 반영 (2026-07-17 새벽) — 각색 금지·재탕 금지

### 23.1 MIT 골격을 채울 때 '그럴듯한 각색'은 날조다
MIT의 공간 동선 칩(입구→등록데스크→컨퍼런스장→…)을 교육용으로 번안하며 실습실·휴게 공간·
발표 공간을 만들어냈다 → 반려 ("동선 따로 없었는데. 등록하고 자리에 앉아서 강의 듣기였는데").
실제 행사는 **단일 강의장(양원선홀), 등록→착석→강의**다. 골격(칩 7개)은 유지하되 내용은
**실제 당일 진행 순서**(등록/착석/오리엔테이션/강의/실습/결과 공유/마무리 — 커리큘럼·서명부·
만족도 화면과 일치)로만. '동선 안내' 서사도 본문·표·소제목 전부에서 걷어냈다 (§15의 확장:
수치만이 아니라 **운영 방식도 지어내면 안 된다**).

### 23.2 칩 제목이 두 문단일 수 있다
MIT 칩2 제목 = `['등록','데스크']` 두 문단 — '등록 데스크' 키로는 안 잡힌다. 문단 단위 키
('등록'→'착석', '데스크'→'')로. 단 같은 텍스트 문단이 그 슬라이드에 또 없는지 확인.
칩 부제에 '90분'까지 쓰면 칩 폭에서 감긴다.

### 23.3 이미 보여준 자산의 재탕 페이지는 여백보다 나쁘다
강의자료 [표지|개요] 미리보기 페이지 → 반려 ("회차별 12컷 페이지가 훨 나았는데").
드라이브 캡처는 '교육 안내·자료 관리' 페이지에 3블록(문자 2열 / 안내화면 3열×2행 / 드라이브
2열)으로 통합 — 페이지 수를 줄이더라도 한 장을 밀도 있게.

### 23.4 PER 딕셔너리에 키를 추가할 때 anchor가 유일한지 확인
'운영팀 운영 성과' 같은 키는 여러 PER에 존재한다 — replace(…, 1)이 엉뚱한 슬라이드 dict에
삽입해 교체가 조용히 누락됐다(실사고). 삽입 후 `grep -n`으로 목적 dict 안인지 확인할 것.

## 24. 인플레이스 XML 패치 트랙 — 사용자 유지 PPT 후속 수정 (2026-07-19, 시민교육 수료증추가 v2)

결보를 한 번 납품한 뒤 사용자가 **파워포인트로 계속 편집·유지하는 본체**(여기선 바탕화면
`결과보고서_시민디지털교육_수료증추가_v2.pptx`, 43장 ~136MB)에 수료증 삽입·수치 갱신·챕터
추가 같은 후속 수정을 가하는 트랙. §0의 "빌드 스크립트 재빌드"와 다르다 — 사용자 편집분을
날리면 안 되므로 **재빌드가 아니라 zip 추출→XML/media 패치→재패키징만** 한다.

### 24.1 작업 원칙 (본체를 절대 오염시키지 않는다)
- **파워포인트 재저장 금지** (zip 파트 중복 손상). 오직 추출→패치→재패키징.
  재패키징은 `[Content_Types].xml`을 **먼저** 쓰고 나머지 트리 순회.
- **매 작업마다 바탕화면 v2를 새로 추출**한다. 그 사이 사용자가 파워포인트로 수정했을 수 있어
  캐시한 추출본을 재사용하면 사용자 편집분을 덮어쓴다. 추출→패치 대상은 항상 최신 원본.
- 저장은 **필요한 파트만** 되돌려 쓰고 나머지는 원본 그대로. 파일이 파워포인트에 열려 잠기면
  cp 실패 → 폴백으로 `..._v2_최신.pptx`에 저장하고 "PPT 닫으면 v2에 반영한다" 안내.
- 이 방식엔 build_final.py·validate.py가 없다 — **LibreOffice 렌더 + 컨택트시트 눈검수**가
  주 검수. 단 OOXML 고유 ID 중복(§24.3)은 LO가 못 잡으니 XML 카운트로 별도 확인.

### 24.2 수료증(규격 이미지) 삽입 — 위치 불변·이미지만 교체
- 수료증 페이지는 이미 디자인된 `<p:pic name="수료증 N">` 프레임 그리드(4열×3행 등)가 있다.
  프레임을 **(y,x)로 정렬**해 좌→우·상→하 순서로 식별하고, 각 프레임의 **이미지 rId(blip
  r:embed)만 교체**한다. off/ext(위치·크기)는 절대 건드리지 않는다 → 규격·간격 자동 유지.
- 규격은 원본 수료증과 **동일 비율**이어야 티가 안 난다(여기선 540×780pt = 0.6923, 슬라이드
  세로 비율과 동일). 배치 순서는 페이지 안에서 **가나다순**으로 통일(김나연→…→황상균).
- 새 media는 `ppt/media/`에 넣고 slide rels에 Relationship 추가, `[Content_Types].xml`에
  jpeg/png Default 있는지 확인. rId·cNvPr id는 슬라이드 내 최대값+1부터 부여(충돌 방지).

### 24.3 표를 복제·증축하면 extLst를 반드시 제거 (재확인 — [[pitfall-pptx-table-extlst]])
`<a:tbl>`의 gridCol/tr/tc를 deepcopy로 늘리면 `a16:colId`/`a16:rowId`가 중복돼 파워포인트에서
**유령 파란 빈 열**이 뜬다. 복제 후 `a:tbl` 내부 `a:extLst`를 **전부** 제거. LibreOffice
미리보기는 이걸 못 잡는다. 참조: scratchpad `add_analysis.py`·`add_4pt.py`의 make_table() 끝.

### 24.4 ⚠️ 챕터 디바이더를 복제로 만들 때 교체할 텍스트 슬롯은 4개 (신규·중요 함정)
새 챕터(예: 04 만족도)를 **다른 챕터의 디바이더 슬라이드 복제**로 만들면, 바꿔야 할 텍스트가
서로 다른 도형에 흩어져 있어 하나만 건드리면 잔재가 남는다. 반드시 4곳 전부 교체·확인:
1. **대제목**(큰 CHAPTER 헤드라인, display) — 예: "과업추진 개요" → "교육 만족도 조사 결과".
2. **인트로 문단**(디바이더 본문 "본 장에서는 …") — 원 챕터 내용 서술이 그대로 복제된다.
3. **하단 푸터 챕터 라벨**(모든 내지에 반복) — 원 챕터 라벨("과업 수행 결과")이 남는다.
4. **좌측 세로 라벨**(아이브로우) — 이건 보통 잊지 않지만 같이 확인.
**실사고**: v2 p39(챕터 04 디바이더)에서 ①대제목이 "과업추진 개요"(챕터 01 잔재), ②인트로가
챕터 03 서술("참여자 모집, 3일간 현장 교육 운영…"), ③p39~43 푸터가 "과업 수행 결과"(챕터 03)로
남았다. 좌측 라벨·섹션 헤더만 "만족도"로 바꿔서 놓친 것. 검증: 새 디바이더 슬라이드 XML에서
`<a:t>` 전량 grep해 **원 챕터 명칭이 하나도 안 남았는지** 확인.

### 24.5 분석·만족도 챕터는 결보 템플릿 실물 복제로만 (자작 도식 금지)
- GPT 분석 원자료를 받아도 **자작 인포그래픽 카드·바 차트는 반려**된다("어색해"). 기존 결보
  슬라이드의 실물 요소 — 밴드(그룹)·소제목 헤더(그룹)·표(표 개체)·다이아 불릿(그룹) — 를
  deepcopy로 가져와 **내용만 교체**한다. set_group_text로 첫 유효 런에 넣고 나머지 런은 비운다.
- **원점수·개별응답·검정통계 raw는 넣지 않는다**("원점수 절대 넣지마"). 보고서 수치·문장만:
  종합 평균·긍정응답률·회차별 평균·상위 주제 비중. 표본 수는 원응답 기준으로 정직하게.
- 표는 make_table()로 행·열을 원하는 만큼 만들되 §24.3(extLst 제거) 필수.
- **통계 용어 금지 (2026-07-19 반려)**: "4점 발생률·전체 4점 중 비중" 같은 표는 비전문가(발주처·
  심사자)가 못 읽는다 → "정량 분석만 한 것 같고 뭔 소리인지 모르겠다"로 반려. **쉬운 말 서사**
  ("참여자는 교육 전반에 매우 만족했습니다" → "강점은 강사·콘텐츠, 보완점은 운영에 모였습니다")
  로 바꾸고 수치는 인포그래픽으로 직관화한다. ↔ §24.5b.

### 24.5b 분석 페이지 인포그래픽 = 도넛(PIL) + 막대 랭킹 + 결론 밴드 (2026-07-19 채택)
§24.5의 "자작 도식 반려"는 **데크 밖 스타일의 어색한 자작**을 말한다. **데크 팔레트·폰트로
깔끔하게, 사용자가 요청**하면 인포그래픽이 정답이다("있어보이게 + 직관적 + 한 페이지 꽉 차게").
실물: v2 p42 재디자인. 참조 구현 scratchpad `p42work/make_donuts.py` + `redesign_p42_v2.py`.
- **도넛(원그래프)은 PIL 슈퍼샘플링 파이슬라이스로 직접 렌더** (venv에 matplotlib 없음).
  4x 확대 pieslice → 중앙 hole 펀치(fill (0,0,0,0)) → LANCZOS 축소, 세그먼트 2° 갭, 중앙 큰
  숫자(Paperlogy ExtraBold)+한글 서브라벨(Pretendard). 투명 PNG를 media에 넣고 make_pic() 배치.
- **표 대신 '막대 랭킹'**: 항목을 값 내림차순 정렬 → [항목명 | 트랙 roundRect(그레이 ECEAE8)
  + 채움 roundRect(값 비례) | 값%]. 순위별 색 그라데(상위 크림슨 D80C18 → 하위 앰버 FF9A52)로
  **최저 항목(=보완 1순위)을 앰버로 플래그** → 도넛의 '보완 집중'과 시각 연결. 0~100 정직 스케일.
- **레이아웃**: 밴드 → ①도넛+요약 → ②막대 랭킹(표 대체) → ③도넛+강점/보완 → 크림슨 결론 밴드.
  §10.1대로 하단까지 채운다(도넛 크기·본문 줄수로 세로 배분, 결론 밴드가 바닥 앵커).
- 텍스트 런은 latin/ea/cs 전부 Pretendard(한글 ea 슬롯 필수). 채운 바 안 텍스트는 band식
  중앙정렬. 막대 값 라벨은 별도 텍스트박스 anchor=ctr로 바와 세로 정렬.

### 24.6 수료자 명단은 서명부(현장 서명)로 확정한다
- 수료 인원·이수율의 근거는 **일자별 참석 서명부**(현장 서명 스캔). 신청/명단이 아니라 실제
  서명 회차 수로 "2일 이상 참석 = 수료"를 판정한다.
- 동명이인·오탈자·이름 혼동은 **반드시 사용자 확인**(예: 박리현=백지헌, 박상근=박상준,
  이우석=이무혁(스태프·제외), 박지웅=박정용). 임의 판단 금지.
- **강사=수료자 모순 배제**: 위촉 강사(프로필·명찰에 등장)는 수료자 명단에 있으면 안 된다
  (실사고: 백지헌). 제외로 목표 인원/이수율이 깨지면 **정당한 대체자로 스왑**해 수치를 유지한다
  (백지헌→박정용, 발급번호 승계, 27명·71.1% 불변). 현장 서명 기록 자체는 사실이므로 지우지 않음.
- 발급번호는 **연속**으로 다시 매긴다(제 2026-107~133). 수치를 하나 바꾸면 연동 수치를 전부
  다시 계산(참석 38·152.0%, 일자별 26/32/29·연인원 87, 수료 27·71.1%·목표대비 +1.1%p).

### 24.7 표지 기관명 = "지식재산전문인력양성사업단"으로 통일 (v2 최종 확정)
발주·직인·협조 주체는 **경북대학교 지식재산전문인력양성사업단**. 초기엔 표지(p1)만 계약 주체인
"산학협력단"으로 두라는 지시가 있었으나, **사용자가 v2 최종본에서 표지도 지식재산전문인력양성
사업단으로 직접 통일**했다(2026-07-19 렌더 확인). 다음 결보 기본값은 전 페이지 동일 기관명.

### 24.8 목차 쪽번호는 챕터 시작 페이지 실측 후, run 유일성 확인하고 교체
페이지를 추가하면 목차 숫자가 어긋난다. 챕터별 시작 슬라이드를 실측(01=3/02=7/03=29/04=39)하고
목차 슬라이드 XML에서 해당 숫자 run이 **유일한지**(`xml.count("<a:t>NN</a:t>")==1`) 확인한 뒤
교체한다. 유일하지 않으면 앞뒤 문맥으로 좁혀서. (이번에 02가 원래부터 06→07로 어긋나 있던 것도
같이 교정.)

### 24.9 복제 템플릿의 '숨은 잔재 도형'은 렌더엔 안 보여도 남는다
MIT 원본을 통째 복사한 페이지에는 화면 밖/뒤에 가려진 **옛 템플릿 도형**(예: 시상 표 "대상
(00만원) 0명 … 상금은 진로취업과에서 지급")이 텍스트로 남아 있을 수 있다. 렌더(썸네일)에는
안 보이지만 텍스트 추출·검색에는 잡히고, 파워포인트에서 우연히 드러날 수 있다. 잔재 스캐너
(BAD 문구 목록, §14·§17)에 "00만원·진로취업과·최우수상" 류를 넣어 감지하고, 여유 있으면
spTree에서 제거한다(위치가 슬라이드 밖이거나 z-순서 뒤라 화면 영향은 없음).
