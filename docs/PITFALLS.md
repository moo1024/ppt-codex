# 함정 — 하나라도 모르면 결과물이 깨진다

렌더가 이상하거나, 파워포인트에서 열었을 때 다르거나, 폰트를 새로 쓸 때 이 문서를 연다.

## 1. 렌더러 구조상의 함정

### 채워진 바 안 텍스트는 반드시 `band` — `card`+별도 `text` 손좌표 금지
(2026-07-19 반려로 확정)

`card`는 텍스트를 못 담는다. 그 위에 `text` 아이템을 눈대중 y로 얹으면:
① 세로 중앙이 안 맞고(텍스트박스는 위쪽 기준) ② 라벨(고정 x)과 본문(고정 x) 사이에
빈 공백이 생기고 ③ 본문이 바 기준 정렬이 안 된다.

SO WHAT·핵심 클로저 바, 하단 캡션 밴드 등 **"채워진 바 안 한 줄 텍스트"는 전부 `band`로.**
band가 vertical_anchor MIDDLE + 라벨·본문 1문단 중앙정렬을 구조적으로 보장한다.

> 예외: 여러 줄을 세로로 쌓는 카드(빅넘버 카드 등)는 원래 손배치가 맞다.

### 한글 폰트는 `<a:ea>` 슬롯
python-pptx의 `font.name`은 라틴 슬롯만 설정한다. 렌더러의 `_set_runs`가 ea/cs를 같이 박는다
— **텍스트는 반드시 렌더러 경유로 생성**(직접 `add_textbox` 금지).

### 유령 그림자
`add_shape`의 `<p:style>` effectRef 때문. `_strip_style()` 사용
(렌더러 프리미티브는 이미 처리됨).

### pill 자동 폭
한글 전각 기준 `_pill_w`로 추정 — 길면 spec에 `w` 명시.

### 형광펜·하이라이트 밴드는 렌더 후 실측 보정
렌더러는 텍스트 폭을 모른다. `_pill_w`식 전각 추정은 헤드라인 폰트에서 **~0.8배 오차**가 난다.
밴드를 깔았으면 반드시 썸네일에서 글자와 맞는지 확인하고 좌표를 실측(픽셀/이미지폭)으로
수정한다. **구절보다 길게 삐져나온 밴드는 즉시 반려감.**

### 빅넘버(num_xl) 밑 헤어라인 겹침
(2026-07-21 반려로 확정)

`num_xl`은 렌더러가 줄간격을 1.0으로 강제한다(기본 1.45는 글자를 박스 아래로 밀어 밑줄과 겹침).
그래도 숫자 폭이 제각각인 카드들을 나란히 둘 땐:
- 헤어라인 y를 숫자 박스보다 **최소 0.04 아래**로
- 세 카드의 숫자/라인/본문 y·구조를 **픽셀 동일하게**

실증: `projects/deepwork` p02.

### `\n` 대신 `lines` 배열
`text`의 `\n` 줄바꿈은 마지막 줄만 행간이 벌어진다. 두 줄 이상은 `lines`로.

### `bars` 프리미티브는 0~5 절대 스케일 — 만족도류에 쓰지 말 것
gyoan.py의 `bars`는 0~5 절대 스케일이라 4.5~4.7 차이가 렌더에서 사라지고 **순서까지 뒤집힌다.**
만족도·평점류는 **card 2겹(트랙 + 채움)으로 직접 작도**하고
폭 = `span × (값 − 4.0)`, 축 눈금 4.0/4.5/5.0 + "구간 확대 표기" 각주를 붙인다.

> **트랙과 채움의 명도차**: 페어 바에서 트랙(F9DCDD)과 채움(E89A9C)이 비슷하면 채움 길이가
> 안 읽혀 **도식이 캡션을 반박한다.** 트랙은 거의 흰색(FDF0F0)으로.

### chip 세로 지름은 `d × 16/9`
슬라이드가 16:9라 chip의 `d`는 가로 기준이다. 라벨 y는 `chip_y + d×1.78 + 0.015`.

### bars 아이템 스키마
`items: [[label, value], ...]` + 색은 테마 고정 — **다크 카드 안에서는 색이 안 맞는다.**
그 자리는 hairline 수동 바로.

### 도형 z-order는 items 배열 순서 그대로
목업 내부 장식을 한 지점에 몰아 삽입하면 **뒤에 오는 카드에 가려진다.**
각 대상 도형 **직후에** 끼워 넣을 것.

### `outline: "none"`은 shape에서 파싱 에러
`int(..., 16)`에서 터진다. 아웃라인이 없으면 **키를 아예 뺀다**
(`fill`은 `"none"`을 허용하지만 `outline`은 아님).

### 불릿 마커와 본문을 한 `text`의 runs로 붙이지 말 것
한글로 시작하는 줄만 LibreOffice CJK 자동간격이 다르게 붙어 **들여쓰기가 어긋난다.**
마커와 본문을 x 고정한 **별도 아이템으로 쪼개면** 해결된다.

### 다열 표 셀의 세로 중앙
열이 많아 `band`를 못 쓰는 자리는 `text` + `h` + `anchor: "middle"`로 잡는다.
카드 안 불릿은 `CW/3` 폭에서 한글 12자를 넘기면 2줄로 흘러 고정 stride가 무너지므로
**카피 길이로 맞춘다.**

### 카드 안 미니 섹션은 스트라이드를 일정하게
라벨+본문 반복 구조는 라벨→본문 0.03, 섹션 간 0.098 정도로 고정.
라벨이 윗 본문에 들러붙으면 줄 리듬이 무너진다.

### 좌측 축은 하나다 (줄맞춤)
(2026-07-20 결보 템플릿에서 "줄맞춤 하나도 안 됐다"로 **두 번** 반려 — 두 번 다 축을 둘로 나눈 것이 원인)

- 시도① 선=마진 / 글자=마진+0.016 → **모든 괘선이 글자보다 왼쪽으로 튀어나옴**
- 시도② 선·글자=마진+0.016 / 컨테이너=마진 → 이번엔 **표·카드가 왼쪽으로 튀어나옴**
- **정답 ③ 괘선·컨테이너·글자 전부 마진(ml).** 눈에 보이는 테두리를 가진 컨테이너
  (표 셀·카드) **안쪽 텍스트만** +PAD(0.016). 컨테이너 가장자리가 정렬 기준을 만들어 주므로
  안쪽 들여쓰기는 어긋나 보이지 않는다.

들여쓰기 사다리(마진 기준): **L2 = +0.050**(소제목·목차 장제목) / **L3 = +0.080**(하위 항목).

**예외는 하나 — `「`로 시작하는 줄.** 여는 낫표는 좌측 사이드베어링이 거의 없어 같은 x에 두면
혼자 왼쪽으로 튀어 보인다. 이 줄만 +0.003 광학 보정(BR 상수).
**그 외 큰 글자 광학 보정은 금지** — 그게 바로 "안 맞아 보이는" 지점이 된다.

**검수는 좌표 + 확대 크롭 둘 다.** 좌표만 보면 시도②처럼 "사다리 통과"인데도 눈에는 어긋난다.
좌측정렬 text/band의 x를 수집하되 center/right 정렬은 제외해야 오탐이 없고, 그 다음 반드시
PIL로 좌측 35% 세로 스트립을 2배 확대해 Read로 눈 확인.
구현체: `projects/gyeolbo-templates/build/build_v3.py` (tx(C)/PAD/L2/L3/BR).

### glow intensity는 0.45~0.65
1.0이면 하단 텍스트가 묻힌다. `cy`를 1.0 밖(1.2~1.4)으로 빼면 은은한 지평선 블룸.

### 다크 커버는 광원과 텍스트를 대각으로 분리
(2026-07-13 확정)

글로우가 우하단이면 텍스트는 좌상~좌중의 어두운 영역에 좌측 정렬로.
광원 위나 중앙에 텍스트를 얹으면 비율이 무너져 보인다.
중앙 정렬 커버가 금지는 아니지만, 그 경우 글로우는 배경 가장자리로.

### PPTX 표 복제 시 extLst
표 행/열을 `deepcopy` 하면 `colId`·`rowId`가 중복돼 파워포인트에서 **유령 빈 열**이 생긴다.
LibreOffice 미리보기로는 안 잡힌다 — `a:tbl` 내 `extLst`를 전부 제거할 것.

## 2. 폰트 — 폰트명은 Windows 레지스트리 등록명 기준
(2026-07-13 파워포인트 폴백 사고로 확정)

사용자는 **한국어 Windows 파워포인트**로 연다. 한글 로컬라이즈명을 가진 폰트는
반드시 한글 이름으로 지정한다.

### 한글명으로 써야 하는 것
더잠실 5 Bold · 에스코어 드림 7 ExtraBold · 비트로 코어 TTF · 던파 비트비트체 v2 ·
G마켓 산스 TTF Bold · KoPubWorld바탕체 Bold · KoPub돋움체 · 한컴산뜻돋움 ·
삼성긴고딕 · 한컴 말랑말랑 · Rix이누아리두리 · 교보 손글씨 2019

### 영문명 유지 그룹
Paperlogy · Pretendard · Freesentation · D2Coding · A2Z · AppleSDGothicNeo(B00 등)

> Paperlogy/Freesentation은 ko 레코드가 "페이퍼로지/프리젠테이션"이지만
> 레지스트리·영문명이 `Paperlogy 8 ExtraBold` 형식이라 **영문명 유지가 맞다**(검증됨).

### 정확한 판정법 (2026-07-13 갱신)
최종 기준은 **사용자 Windows 레지스트리 등록명**. WSL에서 바로 확인 가능:

```bash
/mnt/c/Windows/System32/reg.exe query \
  "HKCU\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts" \
  | iconv -f CP949 -t UTF-8 | grep <이름>
```
(시스템 설치분은 `HKLM`)

Windows는 en(0x409)·ko(0x412) nameID 1을 **둘 다** 매칭하므로 둘 중 하나와 일치하면 된다.

**`fc-list` 이름은 Mac 레코드일 수 있어 믿으면 안 된다.**
함정 사례: Rix이누아리두리는 nameID 1이 `"Rix이누아리두리 Regular"` (Regular 포함).

네임테이블 직접 확인:
```bash
python3 -c "from fontTools.ttLib import TTFont; f=TTFont('폰트.ttf'); \
 print(f['name'].getName(1,3,1,0x412), f['name'].getName(1,3,1,0x409))"
```

### 새 폰트 설치
WSL(`~/.local/share/fonts` + `fc-cache -f`)과 **Windows(사용자 폰트 + 레지스트리) 양쪽**에
있어야 한다.
트로브: `/mnt/c/Users/hansb/Desktop/이무혁/All_Fonts_Backup` (599개, 대부분 Windows에 설치됨)

## 3. 내보내기·썸네일

### 한글·숫자·구두점 사이가 벌어져 보이면
(`"1 년 안에 ,"` 처럼)

LibreOffice의 CJK 자동간격이 안 꺼진 것.
`pptm export`는 **pptx → ODP → autospace 패치 → PDF** 경로가 정상이며,
**"ODP 변환 실패 — 직행 폴백" 경고가 뜨면 그 썸네일은 간격이 오염된 것이니 재실행.**

PPTX 자체는 정상이다(파워포인트는 자동간격이 없음).
**수동 `soffice` 변환으로 검수하지 말 것 — 패치가 빠진다.**

### LibreOffice 썸네일의 1px 흰 선/노치
래스터 아티팩트다. PPTX 자체는 정상이니 무시.
